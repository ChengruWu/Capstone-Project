## 调用链分析

### 第 1 次：贪心，status=ok，但任务未完成

1. **raw** 先说“需要先读取文件并计算测试通过率，请稍等。”，随后输出 `read_file` 调用，路径为 `/content/test_report.txt`。**decision** 带有模型自行补出的绝对路径；**observation** 是路径安全校验返回的 `PermissionError`。
2. **raw** 是道歉和权限说明，并把 `/test_project/test_report.txt` 当成相对路径示例，没有 JSON。因此没有合法 **decision**，trace 记录 `format_error: 输出中没有 JSON 对象`，也没有工具 **observation**。
3. **raw** 为合法的 `final`，answer 是“请提供正确的文件路径以便进行后续操作。”没有成功读取文件或调用 `calculator`。Loop 因 final 格式合法以 `ok` 结束，实际任务仍未完成。

### 第 2 次：开启采样，status=too_many_failures

1. **raw** 包含较长解释，甚至在没有读取数据前提出“所有测试成功则 100%，有失败则 0%”的错误近似，最后输出 read_file JSON，路径为 `/Users/your_username/Desktop/test_report.txt`。**decision** 仍是合法的 read_file 工具调用；**observation** 为 PermissionError，明确给出工作目录内相对路径示例。失败计数为 1。
2. **raw** 声称“我将使用相对路径来尝试读取文件”，但随后的 **decision** 仍使用完全相同的 `/Users/your_username/Desktop/test_report.txt`。**observation** 再次为相同路径导致的 execution_error，失败计数变为 2。这显示自然语言中的“修正”没有落实到实际 arguments。
3. **raw** 声称已经使用正确相对路径、归因于系统配置并放弃任务，全段没有 JSON。没有合法 **decision** 和工具 **observation**，trace 记录 format_error。累计连续失败达到 3，大于 `max_failures=2`，直接返回 `too_many_failures`，answer 为 null。此时终止发生在格式解析异常分支，不再追加格式纠错 Observation。

第 2 次与第 1 次相比只开启了采样。该固定种子下，采样产生重复错误路径调用；这一次观察不能说明温度 0.7 普遍更差。

### 横向观察

- 第 1–5 次始终使用原始提示词，均未成功读取文件。第 3 次将温度从 0.7 降为 0.3，第一步路径为 `/test_report.txt`；第 4、5 次都使用 `/home/user/test_report.txt`。
- 第 4 次只把 top-p 从 0.8 增到 0.95，路径变成 `/home/user/test_report.txt`，仍然是“路径错误 → 非 JSON 解释 → 放弃任务的 final”。
- 第 5 次只把 top-k 从 20 增到 50，raw、decision、observation 与第 4 次相同，只有耗时等运行数据不同。候选截断参数变化不保证实际采样 token 变化；这里没有记录每步概率，不能断言两个配置的候选集合完全相同。
- 五次主要瓶颈都是模型没有遵守相对路径约束，且未正确利用 Observation 修正参数。自测及工作目录验证支持工具本身可用，模型对“环境不支持”的表述不是事实结论。
- 第 1–5 次构成固定提示词的解码参数对照；第 6 次与第 1 次只改变提示词，作为可选拓展。提示词对照中，模型仍输出 `/test_report.txt`，随后在没有成功读取文件的情况下编造统计信息。每组仅运行一次，没有跨种子统计，也没有大模型对照，因此不能推出普遍成功率或更大模型一定有效。

## 可选拓展：识别字符串与转义的 JSON 停止条件

### 修改内容与动机

课程原始代码已经有 `_BalancedJSONStop`，本次拓展是修复已有停止逻辑，不将原有功能或 word_count 工具算作新增成果。原逻辑从第一个 `{` 开始无条件数花括号，导致 answer 字符串内的 `}` 被误认为顶层对象闭合；字符串内的 `{` 则可能导致完整对象生成后仍不停。

增加 `in_string` 与 `escaped` 状态：字符串内只处理引号和反斜杠，不计入花括号深度；字符串外才统计 `{`、`}`。每次只扫描新生成 token 的解码文本，保留原有 token 级停止方式。新增 CLI `--json-stop legacy|string-aware`，默认 string-aware，legacy 精确保留原始括号计数分支。`make_hf_llm` 增加同名参数；新增 `--seed` 和结果中的 config/environment 元数据用于实验记录，不改变 Agent 决策协议和工具校验。

该检测只确定对象边界，不代替 JSON/Pydantic 语法与字段验证，也不裁剪或重写模型 raw。停止以 token 为粒度，单个 token 若含边界后的字符仍会保留。首次 `{` 前出现含花括号的说明文字、批量生成、多对象同 token 等情况不属于本次小拓展解决范围。

### 确定性测试

`test_json_stop.py` 的六项 unittest 全部通过：覆盖完整对象每一个未完成前缀、嵌套对象、字符串内左右花括号、转义引号/反斜杠、无对象与不完整 JSON、代码围栏与连续对象、排除 Prompt、原版提前停止和漏停回归。测试使用字符级假 tokenizer 隔离边界检测逻辑，以下真实模型对照补充验证实际 tokenizer 下的效果。
