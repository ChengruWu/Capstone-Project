## 拓展与结果

- 拓展内容：在原有 JSON Schema 和 Python 语法校验之外，增加安全的 Python 函数契约静态检查。
- 主要改动：新增 `check_function_contract`，使用 AST 检查整棵语法树是否只有一个函数定义（含嵌套函数及类方法），且该函数位于顶层、名称符合期望，首个位置参数名符合要求，代码中没有 import / from import；同时检查 JSON 的 `function_name` 与代码中的函数名一致。增加 `--check-code`、`--expected-function` 和 `--expected-parameter` 参数。检查过程不执行模型生成的代码，不保证算法正确或代码运行安全。
- 开关行为：只有显式传入 `--check-code` 才启用契约检查；`--example` 仅自动启用基础结构化校验。自定义期望参数必须配合 `--check-code` 使用。示例开启契约检查时默认期望 `count_positive(nums)`。
- 运行结果：`example_stream.json` 为 `schema_valid`、`syntax_valid`，契约状态为 `not_requested`；`extension_contract.json` 在相同 Prompt 下额外得到 `contract_valid`。流式响应的 JSON 仍会先完整拼接，再统一解析和校验。
- 普通回答：`plain.json` 返回 `text_received`，模型自然结束，实际生成 216 个 completion tokens。
- 观察与问题：自定义 Prompt 测试记录在 `custom_prompt_failure.json`，模型输出了 Markdown JSON 围栏，导致第一层 JSON 解析即返回 `json_error`，尚未进入 Schema、Python 语法或契约检查。原文中的代码还包含未注释的中文说明，这是另一个潜在语法问题。此次自定义 Prompt 失败，而内置参考 Prompt 成功，说明本次实验中参考示例有助于遵循格式；单次结果不能证明所有 Prompt 的表现。
- 拓展效果与限制：基础示例与拓展实验的模型正文相同，拓展增加的是客户端检查，不改变生成过程。检查器能够拒绝错误函数名、错误首参数、导入语句、多个函数定义、嵌套函数和 JSON 函数名不一致；这些分支另用人工构造输入验证，不冒充模型运行结果。保存的模型结果中 `functional_correctness` 仍为 `not_tested`。
